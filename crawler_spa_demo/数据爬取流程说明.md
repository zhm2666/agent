# MindSpider 数据爬取流程详细说明

> 本文件用于系统性说明 `MindSpider/` 项目是如何完成“从热点发现到多平台深度爬取”的全流程，便于后续开发、排障和扩展。

---

## 1. 项目整体定位

`MindSpider` 是一个面向舆情分析的 AI 爬虫系统，核心思路是：

1. 先从多个热点平台收集当日热点新闻；
2. 再由 AI 自动提炼“话题关键词”；
3. 最后基于这些关键词，在多个社媒平台上做深度爬取，获取帖子和评论内容。

整个系统分为两大部分：

- `BroadTopicExtraction/`：热点发现 + 关键词生成
- `DeepSentimentCrawling/`：基于关键词的多平台深度爬取

入口文件：`MindSpider/main.py`

---

## 2. 顶层调度：`MindSpider/main.py`

`MindSpider/main.py` 是一个 CLI 编排层，负责检查环境、初始化数据库、串联两个子模块。

### 2.1 配置与状态检查

`MindSpider/main.py` 在启动时会做以下检查：

1. 检查 `.env` / `config.py` 中的必要配置是否存在；
2. 检查数据库连接是否正常；
3. 检查必要数据库表是否已存在；
4. 检查 Python 依赖是否满足；
5. 检查 `BroadTopicExtraction/` 与 `DeepSentimentCrawling/` 是否存在。

相关代码：

```python
def check_config(self) -> bool:
    required_configs = [
        'DB_HOST', 'DB_PORT', 'DB_USER', 'DB_PASSWORD', 'DB_NAME', 'DB_CHARSET',
        'MINDSPIDER_API_KEY', 'MINDSPIDER_BASE_URL', 'MINDSPIDER_MODEL_NAME'
    ]
    missing_configs = [
        name for name in required_configs
        if not hasattr(settings, name) or not getattr(settings, name)
    ]
    if missing_configs:
        logger.error(f"配置缺失: {', '.join(missing_configs)}")
        return False
    return True
```

### 2.2 数据库初始化

如果数据库不存在核心表，`MindSpider/main.py` 会调用：

```python
schema/init_database.py
```

来完成建表。核心表结构定义在：

```python
schema/mindspider_tables.sql
```

### 2.3 完整工作流

完整工作流通过 `run_complete_workflow` 串联两个阶段：

```python
def run_complete_workflow(...):
    # 第一步：话题提取
    self.run_broad_topic_extraction(target_date, keywords_count)
    # 第二步：深度情感爬取
    self.run_deep_sentiment_crawling(
        target_date, platforms, max_keywords, max_notes, test_mode
    )
```

这两个子模块分别由 `BroadTopicExtraction/main.py` 和 `DeepSentimentCrawling/main.py` 实现。

## 3. 阶段一：热点话题提取 `BroadTopicExtraction`

### 3.1 模块入口

文件：`BroadTopicExtraction/main.py`

主流程由 `BroadTopicExtraction.run_daily_extraction()` 实现，包含三步：

1. 收集热点新闻
2. AI 提取关键词和总结
3. 保存到数据库

```python
async def run_daily_extraction(self, news_sources=None, max_keywords=100):
    # 步骤1：收集热点新闻
    news_result = await self.news_collector.collect_and_save_news(sources=news_sources)

    # 步骤2：提取关键词和生成总结
    keywords, summary = self.topic_extractor.extract_keywords_and_summary(
        news_result['news_list'], max_keywords=max_keywords
    )

    # 步骤3：保存到数据库
    save_success = self.db_manager.save_daily_topics(
        keywords, summary, date.today()
    )
```

`NewsCollector` 通过第三方公开 API 获取热点数据：

- Base URL：`https://newsnow.busiyi.world`
- 请求路径：`/api/s?id={source}&latest`

核心调用：

```python
async def fetch_news(self, source: str) -> dict:
    url = f"{BASE_URL}/api/s?id={source}&latest"
    headers = {
        "Accept": "application/json, text/plain, */*",
        "User-Agent": "Mozilla/5.0 ...",
        "Referer": BASE_URL,
    }
    async with httpx.AsyncClient(timeout=30.0, follow_redirects=True) as client:
        response = await client.get(url, headers=headers)
        data = response.json()
    return {"source": source, "status": "success", "data": data}
```

#### 3.2.3 数据处理与入库

新闻数据会在入库前做标准化：

```python
def _process_news_item(self, item, source, rank):

    return {
```

`NewsCollector` 会调用 `DatabaseManager.save_daily_news(...)` 写入 `daily_news` 表。

### 3.3 AI 话题提取：`TopicExtractor`

文件：`BroadTopicExtraction/topic_extractor.py`

#### 3.3.1 LLM 调用方式

`TopicExtractor` 使用兼容 OpenAI 格式的 API，默认使用 `MINDSPIDER_API_KEY` / `MINDSPIDER_BASE_URL` / `MINDSPIDER_MODEL_NAME`。

初始化方式：

```python
from openai import OpenAI
self.client = OpenAI(
    api_key=settings.MINDSPIDER_API_KEY,
    base_url=settings.MINDSPIDER_BASE_URL
)
```

#### 3.3.2 Prompt 设计

系统会把“所有热点新闻标题”喂给 LLM，并要求其返回 JSON：

```python
prompt = f"""
请分析以下{news_count}条今日热点新闻，完成两个任务：

新闻列表：
{news_text}

任务1：提取关键词（最多{max_keywords}个）
任务2：撰写新闻分析总结（150-300字）

请严格按照以下JSON格式输出：
{{
  "keywords": ["关键词1", "关键词2", "关键词3"],
  "summary": "今日新闻分析总结内容..."
}}
"""
```

#### 3.3.3 结果解析

`TopicExtractor` 会优先尝试解析 JSON，若失败则降级到手动解析：

```python
response = self.client.chat.completions.create(...)
result_text = response.choices[0].message.content
keywords, summary = self._parse_analysis_result(result_text)
```

解析失败时会触发兜底方案：

```python
fallback_keywords = self._extract_simple_keywords(news_list)
fallback_summary = f"今日共收集到 {len(news_list)} 条热点新闻，涵盖多个平台的热门话题。"
```

### 3.4 数据库存储

`BroadTopicExtraction/database_manager.py` 负责把提取结果写入：

- `daily_news`：存储热点新闻
- `daily_topics`：存储 AI 提取后的关键词和总结
- `topic_news_relation`：存储话题与新闻之间的关联关系（可选扩展）

`daily_topics` 中的 `keywords` 字段以 JSON 字符串形式存储关键词数组，`summary` 存储 AI 生成的新闻总结。

## 4. 阶段二：深度内容爬取 `DeepSentimentCrawling`

### 4.1 模块入口

文件：`DeepSentimentCrawling/main.py`

主流程由 `DeepSentimentCrawling.run_daily_crawling()` 实现：

```python
def run_daily_crawling(self, target_date, platforms=None,
                       max_keywords_per_platform=50, max_notes_per_platform=50,
                       login_type="qrcode"):

    # 1. 获取关键词摘要
    summary = self.keyword_manager.get_crawling_summary(target_date)

    # 2. 获取关键词
    keywords = self.keyword_manager.get_latest_keywords(
        target_date, max_keywords_per_platform
    )

    # 3. 执行全平台关键词爬取
    crawl_results = self.platform_crawler.run_multi_platform_crawl_by_keywords(
        keywords, platforms, login_type, max_notes_per_platform
    )
```

### 4.2 关键词管理：`KeywordManager`

文件：`DeepSentimentCrawling/keyword_manager.py`

#### 4.2.1 关键词读取优先级

`KeywordManager` 按如下优先级读取关键词：

1. 优先读取当天 `daily_topics` 中的关键词；
2. 如果当天没有，读取最近 7 天的历史关键词并合并去重；
3. 如果仍没有，使用内置默认关键词兜底。

```python
def get_latest_keywords(self, target_date, max_keywords=100):
    # 1. 当天
    topics_data = self.get_daily_topics(target_date)
    if topics_data and topics_data.get('keywords'):
        keywords = topics_data['keywords']
        if len(keywords) > max_keywords:
            keywords = random.sample(keywords, max_keywords)
        return keywords

    # 2. 最近7天
    recent_topics = self.get_recent_topics(days=7)
    if recent_topics:
        all_keywords = []
        for topic in recent_topics:
            all_keywords.extend(topic.get('keywords', []))
        unique_keywords = list(set(all_keywords))
        if len(unique_keywords) > max_keywords:
            unique_keywords = random.sample(unique_keywords, max_keywords)
        return unique_keywords

    # 3. 默认关键词
    return self._get_default_keywords()
```

#### 4.2.2 数据库连接

`KeywordManager` 使用 SQLAlchemy 的同步引擎连接数据库，支持 MySQL 与 PostgreSQL：

```python
dialect = (settings.DB_DIALECT or "mysql").lower()
if dialect in ("postgresql", "postgres"):
    url = f"postgresql+psycopg://{settings.DB_USER}:{settings.DB_PASSWORD}@..."
else:
    url = f"mysql+pymysql://{settings.DB_USER}:{settings.DB_PASSWORD}@..."
self.engine = create_engine(url, future=True)
```

### 4.3 平台爬虫管理：`PlatformCrawler`

文件：`DeepSentimentCrawling/platform_crawler.py`

这是阶段二中最核心的组件，但它**并不自己实现爬虫**，而是通过“修改配置 + 子进程调用”的方式，复用 `MediaCrawler` 的能力。

#### 4.3.1 配置注入：数据库配置重写

`PlatformCrawler` 会修改 `MediaCrawler/config/db_config.py`，把 MediaCrawler 的数据库指向 MindSpider 自己的数据库：

```python
def configure_mediacrawler_db(self):
    db_config_path = self.mediacrawler_path / "config" / "db_config.py"
    with open(db_config_path, 'r', encoding='utf-8') as f:
        content = f.read()

    new_config = f'''# mysql config - 使用MindSpider的数据库配置
MYSQL_DB_PWD = "{config.settings.DB_PASSWORD}"
MYSQL_DB_USER = "{config.settings.DB_USER}"
MYSQL_DB_HOST = "{config.settings.DB_HOST}"
MYSQL_DB_PORT = {config.settings.DB_PORT}
MYSQL_DB_NAME = "{config.settings.DB_NAME}"

mysql_db_config = {{
    "user": MYSQL_DB_USER,
    "password": MYSQL_DB_PWD,
    "host": MYSQL_DB_HOST,
    "port": MYSQL_DB_PORT,
    "db_name": MYSQL_DB_NAME,
}}
'''

    with open(db_config_path, 'w', encoding='utf-8') as f:
        f.write(new_config)
```

#### 4.3.2 配置注入：运行参数重写

`PlatformCrawler` 还会修改 `MediaCrawler/config/base_config.py`，把平台、关键词、爬取数量等运行时参数写进去：

```python
def create_base_config(self, platform, keywords, crawler_type="search", max_notes=50):
    base_config_path = self.mediacrawler_path / "config" / "base_config.py"
    keywords_str = ",".join(keywords)

    with open(base_config_path, 'r', encoding='utf-8') as f:
        content = f.read()
    lines = content.split('\n')
    new_lines = []

    for line in lines:
        if line.startswith('PLATFORM = '):
            new_lines.append(f'PLATFORM = "{platform}"')
        elif line.startswith('KEYWORDS = '):
            new_lines.append(f'KEYWORDS = "{keywords_str}"')
        elif line.startswith('CRAWLER_TYPE = '):
            new_lines.append(f'CRAWLER_TYPE = "{crawler_type}"')
        elif line.startswith('SAVE_DATA_OPTION = '):
            new_lines.append(f'SAVE_DATA_OPTION = "{save_data_option}"')
        elif line.startswith('CRAWLER_MAX_NOTES_COUNT = '):
            new_lines.append(f'CRAWLER_MAX_NOTES_COUNT = {max_notes}')
        elif line.startswith('ENABLE_GET_COMMENTS = '):
            new_lines.append('ENABLE_GET_COMMENTS = True')
        elif line.startswith('HEADLESS = '):
            new_lines.append('HEADLESS = True')
        else:
            new_lines.append(line)

    with open(base_config_path, 'w', encoding='utf-8') as f:
        f.write('\n'.join(new_lines))
```

#### 4.3.3 子进程调用

配置改完后，`PlatformCrawler` 会以子进程方式启动 MediaCrawler：

```python
cmd = [
    sys.executable, "main.py",
    "--platform", platform,
    "--lt", login_type,
    "--type", "search",
    "--save_data_option", save_data_option
]

result = subprocess.run(
    cmd,
    cwd=self.mediacrawler_path,
    timeout=3600
)
```

#### 4.3.4 全平台调度逻辑

`run_multi_platform_crawl_by_keywords` 的调度策略是：

- **对每个平台**，一次性把该批次所有关键词传给 MediaCrawler；
- MediaCrawler 内部会按关键词进行搜索并爬取内容；
- `PlatformCrawler` 收集每个平台的统计结果，汇总为总报告。

```python
for platform in platforms:
    result = self.run_crawler(platform, keywords, login_type, max_notes_per_keyword)
    if result.get("success"):
        total_stats["successful_tasks"] += len(keywords)
    else:
        total_stats["failed_tasks"] += len(keywords)
```

这种设计的核心好处是：**每个平台的爬虫任务都隔离在独立子进程中，互不影响。**

## 5. 底层爬虫原理：`MediaCrawler`

`MediaCrawler` 是一个独立的开源项目，`MindSpider` 将其作为子模块引入并复用。

### 5.1 技术栈

- **浏览器自动化**：Playwright
- **登录态保持**：首次需扫码，后续复用浏览器上下文
- **签名参数获取**：通过 JS 表达式在浏览器环境里获取签名，无需逆向 JS
- **数据存储**：支持 CSV、JSON、SQLite、MySQL、PostgreSQL
- **异步并发**：使用 AsyncIO 提升爬取效率

### 5.2 支持平台

| 平台 | 代码 |
|------|------|
| 小红书 | `xhs` |
| 抖音 | `dy` |
| 快手 | `ks` |
| B站 | `bili` |
| 微博 | `wb` |
| 贴吧 | `tieba` |
| 知乎 | `zhihu` |

### 5.3 登录与缓存

- 首次运行需要扫码登录；
- 登录状态保存在 `DeepSentimentCrawling/MediaCrawler/browser_data/` 下；
- 后续运行可直接复用，无需重复登录。

部分平台（如 `xhs`、`dy`）还支持通过 CDP 连接本地浏览器。

## 6. 数据库设计

### 6.1 核心表说明

主要表结构定义在 `schema/mindspider_tables.sql`。

#### `daily_news`

存储每日从各平台收集到的热点新闻。

| 字段 | 说明 |

| `news_id` | 新闻唯一 ID，格式一般为 `{source}_{原始id}` |

| `title` | 新闻标题 |
| `url` | 新闻链接 |
| `description` | 新闻描述 |
| `crawl_date` | 爬取日期 |
| `rank_position` | 热榜排名 |

#### `daily_topics`

存储 AI 提取的每日话题信息。

| 字段 | 说明 |
|------|------|
| `topic_id` | 话题唯一 ID |
| `topic_name` | 话题名称 |
| `topic_description` | 话题描述 |
| `keywords` | 关键词列表，JSON 格式 |
| `extract_date` | 提取日期 |
| `relevance_score` | 相关性得分 |
| `news_count` | 关联新闻数量 |
| `processing_status` | 处理状态 |

#### `topic_news_relation`

话题与新闻的关联关系表。

| 字段 | 说明 |
|------|------|
| `topic_id` | 话题 ID |
| `news_id` | 新闻 ID |
| `relation_score` | 关联度得分 |

#### `crawling_tasks`

记录每个平台、每个话题对应的爬取任务状态。

| 字段 | 说明 |
|------|------|
| `task_id` | 任务唯一 ID |
| `topic_id` | 关联话题 ID |
| `platform` | 目标平台 |
| `search_keywords` | 搜索关键词，JSON 格式 |
| `task_status` | 任务状态 |
| `start_time` / `end_time` | 起止时间 |
| `total_crawled` / `success_count` / `error_count` | 爬取统计 |
| `config_params` | 爬取配置参数，JSON 格式 |

#### `MediaCrawler` 平台内容表

- `xhs_note`
- `douyin_aweme`
- `kuaishou_video`
- `bilibili_video`
- `weibo_note`
- `tieba_note`
- `zhihu_content`

扩展字段包括：

- `topic_id`
- `crawling_task_id`

### 6.2 视图

- `v_topic_crawling_stats`：每个话题的爬取统计

## 9. 扩展方式

### 9.1 扩展新闻源

在 `BroadTopicExtraction/get_today_news.py` 中新增来源：

```python
SOURCE_NAMES = {
    ...
    "new-platform": "新平台热榜",
}
```

并保证该来源的 API 返回格式兼容现有的 `items` 列表结构。

### 9.2 扩展平台爬虫

在 `DeepSentimentCrawling/MediaCrawler/media_platform/` 下新增平台目录，并实现：

- `client.py`
- `core.py`
- `login.py`
- `field.py`

然后在 `DeepSentimentCrawling/platform_crawler.py` 的 `supported_platforms` 中注册新平台。

### 9.3 扩展数据库表

在 `schema/mindspider_tables.sql` 中新增表定义，再执行：

```bash
python schema/init_database.py
```

## 10. 常见问题与调优建议

### 10.1 登录失败

- 修改 `MediaCrawler/config/base_config.py`：
  ```python
  HEADLESS = False
  ```
- 删除 `MediaCrawler/browser_data/` 后重新登录。

### 10.2 爬取数据为空

- 先确认平台已成功登录；
- 确认先执行过话题提取；
- 使用 `--test` 小规模验证：
  ```bash
  python main.py --complete --test
  ```

### 10.3 性能与稳定性

- 控制并发与爬取数量，避免触发平台限流；
- 使用代理池提升稳定性；
- 定期检查 `crawling_tasks` 的任务状态；
- 使用 `v_daily_summary`、`v_topic_crawling_stats` 观察每日进展。
