## 1. 为什么需要「状态」？

第 1 章的老虎机没有状态：不管第几次拉，下一次做决策跟过去无关。

但现实中很多问题**有连续性**：

- 下棋：你现在看到的棋盘（状态）决定你能走哪步
- 开车：你现在在哪儿、速度多少（状态）决定该加油还是刹车
- 走迷宫：你在哪个格子（状态）决定下一步往哪走

这些问题的共同点：**「我现在做的决定 + 我现在在哪」共同决定未来**。

---

## 2. 本章要解决什么问题

我们用一个**网格世界（GridWorld）**作为例子：

```
奖励矩阵 (reward_map):
[[ 0. ,  0. ,  0. ,  1.0],   ← (0,3) 目标 +1
 [ 0. , None,  0. , -1.0],   ← (1,1) 墙，(1,3) 陷阱 -1
 [ 0. ,  0. ,  0. ,  0. ]]   ← (2,0) 起点
```

智能体从 `(2,0)` 出发，每步可向上下左右（4 个动作），走到目标 +1、掉陷阱 -1，其它格 0。

如果**我们完全知道**环境的规则（每个动作会到哪个状态、给多少奖励），能不能**直接算**出每个格子有多值？怎么算出最优策略？

**能。** 这就是动态规划。

---

## 3. 核心概念：价值 V(s)

**V(s) = 状态 s 的价值** = 从 s 出发，按策略 π 行动，能拿到的**长期平均奖励**。

例子：走到目标前那一格价值应该很高，因为再走一步就能 +1。陷阱旁边那一格价值应该是负数。

V(s) 的**用处**：到达一个状态后，选择**邻居中 V 值最高**的方向走。

---

## 4. 核心公式：Bellman 方程

第 4 章最核心的公式，**Bellman 方程**：

$$
V(s) = \sum_{a} \pi(a|s) \sum_{s'} P(s'|s, a) \big[ R(s, a, s') + \gamma V(s') \big]
$$

逐项翻译：

- `V(s)`：状态 s 的价值
- `π(a|s)`：在 s 选动作 a 的概率
- `P(s'|s, a)`：在 s 做 a 转移到 s' 的概率
- `R(s, a, s')`：这个转移的奖励
- `γ`（gamma）：折扣因子
- `V(s')`：下一个状态 s' 的价值

大白话：**「一个状态的价值 = 我现在选每个动作的奖励 + 未来的折现价值，按概率加权」**

**关键洞察**：Bellman 方程是个**递推**式——可以**用邻居的价值算自己的价值**。

## 5. 第 1 个脚本：dp.py（两个状态的 Bellman 方程）

### 5.1 场景

假设只有两个状态 `L1` 和 `L2`，每个状态各有 2 个动作：

```
L1: 动作1 → 奖励 1 → L2
    动作2 → 奖励 0 → L1
L2: 动作1 → 奖励 -1 → L1
    动作2 → 奖励 0 → L2
```

每个动作各 50% 概率被选，γ = 0.9。

### 5.2 含义

按 Bellman 方程：

$$
V(L1) = 0.5 \cdot (-1 + 0.9 V(L1)) + 0.5 \cdot (1 + 0.9 V(L2))
$$

$$
V(L2) = 0.5 \cdot (0 + 0.9 V(L1)) + 0.5 \cdot (-1 + 0.9 V(L2))
$$

### 5.3 代码

```python
V = {'L1': 0.0, 'L2': 0.0}
new_V = V.copy()
cnt = 0

while True:
    new_V['L1'] = 0.5 * (-1 + 0.9 * V['L1']) + 0.5 * (1 + 0.9 * V['L2'])
    new_V['L2'] = 0.5 * ( 0 + 0.9 * V['L1']) + 0.5 * (-1 + 0.9 * V['L2'])

    delta = abs(new_V['L1'] - V['L1'])
    delta = max(delta, abs(new_V['L2'] - V['L2']))
    V = new_V.copy()

    cnt += 1
    if delta < 0.0001:
        print(V)
        print(cnt)
        break
```

### 5.4 解读

1. **初始化 V = 0**（智能体什么都不知道）
2. **反复更新**（用旧 V 算新 V 的全部格子）
3. **检查变化量** delta：所有格子的 |新 - 旧| 最大值
4. 当 delta < 0.0001，认为**收敛**了，停止

跑几十年乃至几百年才能收敛到这里，**但能收敛**。Bellman 方程是**压缩映射**，数学上必然收敛。

### 5.5 输出示例

```
{'L1': -0.25, 'L2': -0.62}  # 收敛值（具体数值取决于题目）
cnt = 76                    # 多少次迭代
```

**注意**：这个解不一定是 「0」，因为奖励里既有正也有负。

## 6. 第 2 个脚本：dp_inplace.py（原地更新）

`dp.py` 里用 `new_V = V.copy()` 算出所有新值再统一覆盖 `V`，这种叫**同步更新**。

`dp_inplace.py` **直接覆盖**：

```python
V = {'L1': 0.0, 'L2': 0.0}
cnt = 0
while True:
    t = 0.5 * (-1 + 0.9 * V['L1']) + 0.5 * (1 + 0.9 * V['L2'])  # ← 用 V 的旧值
    delta = abs(t - V['L1'])
    V['L1'] = t                                                  # ← 立刻覆盖

    t = 0.5 * (0 + 0.9 * V['L1']) + 0.5 * (-1 + 0.9 * V['L2'])  # ← 这里 V['L1'] 已经是新值了！
    delta = max(delta, abs(t - V['L2']))
    V['L2'] = t
    cnt += 1
    if delta < 0.0001:
        break
```

### 6.1 同步 vs 原地：哪种好？

| 同步更新 | 原地更新 |
| --- | --- |
| 算全部新值再统一覆盖 | 算一个就覆盖一个 |
| 数学收敛速度稳定 | 通常**更快**收敛 |
| 实现稍麻烦 | 实现简单 |

原地更新**信息更新更快**（因为新算的马上影响下次），实践中收敛更快。Gauss-Seidel 迭代的原理。

## 8. 第 4 个脚本：policy_eval.py（策略评估）

### 8.1 概念

**策略评估（Policy Evaluation）**：给定一个策略 π，算每个状态的价值 V。

也就是反复迭代 Bellman 方程直到收敛。它不和改进策略，只回答「按这个策略玩，每个状态值多少分」。

### 8.2 主循环

```python
def eval_onestep(pi, V, env, gamma=0.9):
    for state in env.states():
        if state == env.goal_state:
            V[state] = 0
            continue

        action_probs = pi[state]
        new_V = 0
        for action, action_prob in action_probs.items():
            next_state = env.next_state(state, action)
            r = env.reward(state, action, next_state)
            new_V += action_prob * (r + gamma * V[next_state])  # Bellman 期望
        V[state] = new_V
    return V

def policy_eval(pi, V, env, gamma, threshold=0.001):
    while True:
        old_V = V.copy()
        V = eval_onestep(pi, V, env, gamma)
        delta = max(abs(V[s] - old_V[s]) for s in V.keys())
        if delta < threshold:
            break
    return V
```

### 8.3 比如：均匀随机策略

```python
pi = defaultdict(lambda: {0: 0.25, 1: 0.25, 2: 0.25, 3: 0.25})
V = defaultdict(lambda: 0)
V = policy_eval(pi, V, env, gamma=0.9)
env.render_v(V, pi)
```

跑完会看到：

- 目标 `(0,3)` 附近格子价值为正
- 陷阱 `(1,3)` 附近价值为负
- 距离越远，价值越接近 0（因为 γ 折扣）

## 9. 第 5 个脚本：policy_iter.py（策略迭代）

### 9.1 流程

**策略迭代（Policy Iteration）** = 反复执行两个步骤：

```
┌─────────────────────────────────────┐
│  1. 策略评估（PE）：算出 V^π         │
│  2. 策略改进（PI）：根据 V^π 改 π   │
│  3. 如果 π 没变 → 收敛！            │
└─────────────────────────────────────┘
```

### 9.2 策略改进（贪婪改进）

对于每个状态 s：

$$
\pi'(s) = \arg\max_a \sum_{s'} P(s'|s,a) [R(s,a,s') + \gamma V(s')]
$$

大白话：**在 s 选哪个动作，能让我直接拿到 + 未来的总和最大？**

### 9.3 代码

```python
def greedy_policy(V, env, gamma):
    pi = {}
    for state in env.states():
        action_values = {}
        for action in env.actions():
            next_state = env.next_state(state, action)
            r = env.reward(state, action, next_state)
            value = r + gamma * V[next_state]
            action_values[action] = value

        max_action = argmax(action_values)
        action_probs = {0: 0, 1: 0, 2: 0, 3: 0}
        action_probs[max_action] = 1.0  # 纯贪心
        pi[state] = action_probs
    return pi

def policy_iter(env, gamma, threshold=0.001):
    pi = defaultdict(lambda: {0: 0.25, 1: 0.25, 2: 0.25, 3: 0.25})
    V = defaultdict(lambda: 0)

    while True:
        V = policy_eval(pi, V, env, gamma, threshold)  # 1) 评估
        new_pi = greedy_policy(V, env, gamma)            # 2) 改进

        if new_pi == pi:                                 # 3) 收敛？
            break
        pi = new_pi
    return pi
```

### 9.4 直观过程

```
初始 π（均匀随机）
   ↓ 评估
得到粗糙的 V
   ↓ 改进
得到新的 π（开始体现方向）
   ↓ 评估
得到更准的 V
   ↓ 改进
收 敛！
```

代码里 `env.render_v(V, pi)` 在每轮显示当前 V 和 π。你能看到图一步步变清晰。

## 10. 第 6 个脚本：value_iter.py（价值迭代）

### 10.1 核心思想

策略迭代里**每轮策略评估都要跑到收敛**，很慢。**价值迭代观察到：评估只要跑 1 步也够，然后立即改进**。

### 10.2 公式

$$
V_{k+1}(s) = \max_a \sum_{s'} P(s'|s,a) [R(s,a,s') + \gamma V_k(s')]
$$

差别就在那个 `max` —— 不再是按策略取期望，而是**取最优动作**。

### 10.3 代码

```python
def value_iter_onestep(V, env, gamma):
    for state in env.states():
        if state == env.goal_state:
            V[state] = 0
            continue

        action_values = []
        for action in env.actions():
            next_state = env.next_state(state, action)
            r = env.reward(state, action, next_state)
            value = r + gamma * V[next_state]
            action_values.append(value)

        V[state] = max(action_values)
    return V

def value_iter(V, env, gamma, threshold=0.001):
    while True:
        old_V = V.copy()
        V = value_iter_onestep(V, env, gamma)
        delta = max(abs(V[s] - old_V[s]) for s in V.keys())
        if delta < threshold:
            break
    return V
```

### 10.4 跑完之后

```python
V = value_iter(V, env, gamma=0.9)
pi = greedy_policy(V, env, gamma)  # V 收敛后，贪心出策略
env.render_v(V, pi)
```

## 11. 策略迭代 vs 价值迭代：两种 DP 的对比

| 维度 | 策略迭代 | 价值迭代 |
| --- | --- | --- |
| 每轮流程 | 评估 PI → 改进 PI | 单步 max 更新 |
| 策略评估 | 跑到收敛 | **只跑 1 步** |
| 收敛速度 | 轮数少，但每轮开销大 | 轮数多，但每轮开销小 |
| 直观性 | 强：「先看准，再改策略」 | 弱：「只更新 V，策略最后才提取」 |
| 实际性能 | 通常更快 | 通常也够用 |

**两者数学上等价，都收敛到 V***。价值迭代可以理解为策略迭代的「省力版」。

## 12. DP 的局限性：为什么后面还要 MC 和 TD？

DP 看似完美，**但有三个大问题**：

### 12.1 必须知道全部环境模型

DP 需要：
- `P(s'|s,a)`：每个动作的转移概率
- `R(s,a,s')`：每个转移的奖励

**真实环境往往没有**。比如机器人走路，你没法写出精确的转移概率——只能让机器人**真的走一遍**去观测。

### 12.2 计算量爆炸

状态空间大时（比如围棋 10^170 状态），DP 算不动。

### 12.3 不能边走边学

DP 是先在脑子里推演，再去执行。真实学习往往需要**边走边学**。

### 12.4 后面的解决方案

| 章 | 方法 | 解决 DP 的什么问题 |
| --- | --- | --- |
| 第 5 章 | 蒙特卡洛（MC） | 不需要模型，只要能跑出轨迹 |
| 第 6 章 | TD / SARSA / Q 学习 | 边走边学，每步更新 |
| 第 7 章 | 神经网络 | 解决状态空间大的问题 |
| 第 8 章 | DQN | 经验回放 + 目标网络 |
| 第 9 章 | 策略梯度 | 直接学策略，不学 V |

**但 DP 的 Bellman 方程是贯穿整本书的灵魂**。后面所有算法都是「如何**近似** Bellman 方程但不需要完整模型」。

## 附：第 4 章 → 第 5 章的过渡

第 4 章是**白板推演**——在脑子里算清楚每一步。

第 5 章开始**真正去走**——从头到尾跑完一条轨迹，再回头算。这种「先行动后总结」的方法就是**蒙特卡洛（Monte Carlo, MC）**。

DP 给我们理论（Bellman 方程），MC 给我们**实践**（实操中如何用样本估计期望）。两者配合，才是完整的强化学习。
