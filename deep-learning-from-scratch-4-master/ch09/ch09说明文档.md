## 1. 为什么需要策略梯度？

### 1.1 Q 学习系列的局限

DQN 学的是 Q 值，策略是 `π(s) = argmax_a Q(s, a)`。

这个范式有以下问题：

| 问题 | 说明 |
| --- | --- |
| **连续动作** | argmax 在无限动作上没法算 |
| **只能学到确定策略** | Q 相同的动作随机选一个，没办法学「30% 左、70% 右」 |
| **奖励稀疏** | Q 反馈很慢，策略梯度可以更直接 |

### 1.2 策略梯度的优势

| 优势 | 说明 |
| --- | --- |
| **连续动作** | 策略输出高斯分布的 μ、σ |
| **学到随机策略** | 比如石头剪刀布必须 1/3 分布 |
| **直接优化目标** | 不用绕一层 Q 值 |

### 1.3 代价

- **高方差**：单步奖励信号噪声大
- **训练慢**：要用大量回合
- **连续动作除外**：策略梯度是唯一选择

## 2. 核心思想：把策略参数化

### 2.1 策略网络

```python
class Policy(Model):
    def __init__(self, action_size):
        super().__init__()
        self.l1 = L.Linear(128)
        self.l2 = L.Linear(action_size)

    def forward(self, x):
        x = F.relu(self.l1(x))
        x = F.softmax(self.l2(x))
        return x
```

输入：状态 s（4 维 CartPole 状态）
输出：每个动作的**概率**（2 个动作 → 2 维概率向量）

### 2.2 选动作

```python
def get_action(self, state):
    state = state[np.newaxis, :]
    probs = self.pi(state)
    probs = probs[0]
    action = np.random.choice(len(probs), p=probs.data)
    return action, probs[action]
```

不是 `argmax`，而是**按概率采样**。这意味着智能体可以学到「30% 概率选 0，70% 概率选 1」。

### 2.3 训练目标

最大化**期望总奖励**：

$$
J(\theta) = E_\tau \big[ G(\tau) \big] = E_\tau \big[ \sum_t r_t \big]
$$

其中 $\tau$ 是一条轨迹。

## 3. 策略梯度公式：为什么是 log π？

### 3.1 梯度公式

$$
\nabla_\theta J(\theta) = E_\tau \big[ \sum_t \nabla_\theta \log \pi_\theta(a_t | s_t) \cdot G_t \big]
$$

### 3.2 直观解释

- `π(a_t | s_t)`：智能体**实际选**动作 a_t 的概率
- `G_t`：这个动作**最终拿到的总回报**
- `log π` 的梯度：表示「**让 π 增大还是减小**」的方向

调整规则：

- 如果 G_t **很大**（这个动作带来了好结果）→ 把 π(a_t | s_t) **调大**
- 如果 G_t **很小**（这个动作带来了差结果）→ 把 π(a_t | s_t) **调小**

### 3.3 为什么用 log π？

数学上：`∇log π = ∇π / π`，归一化后**梯度不会因为 π 本身的大小而偏差**。

如果 π=0.99，log π 变化小；
如果 π=0.01，log π 变化大。

→ 罕见的「幸运动作」被给予更大梯度，刚好鼓励探索。

### 3.4 损失函数

策略梯度**最大化** J，但训练框架都是**最小化**损失。所以取负：

$$
L = -\sum_t \log \pi(a_t | s_t) \cdot G_t
$$

## 4. 第 1 个脚本：simple_pg.py（带基线的 REINFORCE）

### 4.1 完整代码

```python
class Policy(Model):
    def __init__(self, action_size):
        super().__init__()
        self.l1 = L.Linear(128)
        self.l2 = L.Linear(action_size)

    def forward(self, x):
        x = F.relu(self.l1(x))
        x = F.softmax(self.l2(x))
        return x

class Agent:
    def __init__(self):
        self.gamma = 0.98
        self.lr = 0.0002
        self.action_size = 2

        self.memory = []
        self.pi = Policy(self.action_size)
        self.optimizer = optimizers.Adam(self.lr)
        self.optimizer.setup(self.pi)

    def get_action(self, state):
        state = state[np.newaxis, :]
        probs = self.pi(state)
        probs = probs[0]
        action = np.random.choice(len(probs), p=probs.data)
        return action, probs[action]

    def add(self, reward, prob):
        self.memory.append((reward, prob))

    def update(self):
        self.pi.cleargrads()

        G, loss = 0, 0
        for reward, prob in reversed(self.memory):
            G = reward + self.gamma * G    # ← 倒着算 G

        for reward, prob in self.memory:
            loss += -F.log(prob) * G       # ← log π × G（已经算过了）

        loss.backward()
        self.optimizer.update()
        self.memory = []
```

### 4.2 三步流程

1. **采样**：玩一回合，每步记 `(reward, prob)`
2. **倒序算 G**：从回合末尾开始累积折扣
3. **更新**：所有步用**同一个 G**（基线版）

### 4.3 「基线」是什么意思？

原始 REINFORCE 用每步的 G_t：

$$
\nabla J = E[\sum_t \nabla \log \pi(a_t|s_t) \cdot G_t]
$$

带基线的 REINFORCE 用**整回合的总 G**：

$$
\nabla J = E[\sum_t \nabla \log \pi(a_t|s_t) \cdot G]
$$

**好处**：所有步共享一个 G，相当于把每步的「相对好坏」标准化。

**坏处**：丢失时间信息（开头和结尾的步骤被同等对待）。

### 4.4 训练循环

```python
for episode in range(3000):
    state = env.reset()
    done = False
    sum_reward = 0

    while not done:
        action, prob = agent.get_action(state)
        next_state, reward, done, info = env.step(action)
        agent.add(reward, prob)
        state = next_state
        sum_reward += reward

    agent.update()    # ← 回合结束才更新
    reward_history.append(sum_reward)
```

每跑完一回合，更新一次策略。

## 5. 第 2 个脚本：reinforce.py（REINFORCE 完整版）

### 5.1 与 simple_pg 的关键区别

```python
def update(self):
    self.pi.cleargrads()
    G, loss = 0, 0
    for reward, prob in reversed(self.memory):
        G = reward + self.gamma * G         # ← 倒序算 G_t
        loss += -F.log(prob) * G            # ← 每步用各自的 G_t
    loss.backward()
    self.optimizer.update()
    self.memory = []
```

### 5.2 区别在哪？

- `simple_pg.py`：用整回合的总 G（**带基线**）
- `reinforce.py`：倒序算每步的 G_t（**原始 REINFORCE**）

### 5.3 哪个更好？

| 维度 | simple_pg | reinforce |
| --- | --- | --- |
| G 计算 | 共享一个 G | 每步 G_t 不同 |
| 时间信息 | 丢失 | 保留 |
| 实践效果 | 通常更稳 | 方差较大 |
| 理论基础 | 弱 | 强（标准 REINFORCE） |

实际中 `simple_pg.py` 也常被叫「REINFORCE with baseline」，效果往往更好。

### 5.4 训练出来什么样？

CartPole：

- 早期：reward 接近 10~30
- 中期：100+ 
- 后期：稳定 195+（满分）

## 6. 第 3 个脚本：actor_critic.py（A2C 风格）

### 6.1 核心思想

**Actor（演员）**：策略网络 π(a|s; θ)
**Critic（评论家）**：价值网络 V(s; w)

- **Actor** 用策略梯度更新
- **Critic** 用 TD 误差更新
- 用 Critic 的价值作为 Actor 的「基线」

### 6.2 两个网络

```python
class PolicyNet(Model):
    def __init__(self, action_size=2):
        super().__init__()
        self.l1 = L.Linear(128)
        self.l2 = L.Linear(action_size)

    def forward(self, x):
        x = F.relu(self.l1(x))
        x = F.softmax(self.l2(x))
        return x

class ValueNet(Model):
    def __init__(self):
        super().__init__()
        self.l1 = L.Linear(128)
        self.l2 = L.Linear(1)

    def forward(self, x):
        x = F.relu(self.l1(x))
        x = self.l2(x)
        return x
```

两个网络可以**共享层**，但这里分开。

### 6.3 update 详解

```python
def update(self, state, action_prob, reward, next_state, done):
    state = state[np.newaxis, :]
    next_state = next_state[np.newaxis, :]

    # ========== (1) 更新 V 网络 ===========
    target = reward + self.gamma * self.v(next_state) * (1 - done)
    target.unchain()                             # ← target 切断梯度
    v = self.v(state)
    loss_v = F.mean_squared_error(v, target)

    # ========== (2) 更新 π 网络 ===========
    delta = target - v                           # ← TD 误差
    delta.unchain()                              # ← delta 当常数
    loss_pi = -F.log(action_prob) * delta        # ← 策略梯度 × TD 误差

    self.v.cleargrads()
    self.pi.cleargrads()
    loss_v.backward()
    loss_pi.backward()
    self.optimizer_v.update()
    self.optimizer_pi.update()
```

### 6.4 关键技巧：TD 误差作为优势

$$
\delta = r + \gamma V(s') - V(s)
$$

δ 的含义：

- **δ > 0**：这一步比预期好，让相应动作的概率增大
- **δ < 0**：这一步比预期差，让相应动作的概率减小

这是 **A2C（Advantage Actor-Critic）** 的核心：δ 是 **advantage（优势）** 的无偏估计。

### 6.5 三种角色分工

| 角色 | 干什么 | 比喻 |
| --- | --- | --- |
| **Actor** π | 选动作 | 演员 |
| **Critic** V | 评判状态有多好 | 评论家 |
| **TD 误差 δ** | 信号 | 演出后观众的反应 |

### 6.6 训练循环

```python
for episode in range(3000):
    state = env.reset()
    done = False
    total_reward = 0

    while not done:
        action, prob = agent.get_action(state)
        next_state, reward, done, info = env.step(action)
        agent.update(state, prob, reward, next_state, done)  # ← 每步都更新！
        state = next_state
        total_reward += reward

    reward_history.append(total_reward)
```

**关键**：**每步都更新**，不像 REINFORCE 要等回合结束。

这是 AC 相对 REINFORCE 的最大优势：**不需要等回合结束**。

## 7. 三种算法的对比

### 7.1 性能对比

| 算法 | 何时更新 | 方差 | 偏差 | 实践表现 |
| --- | --- | --- | --- | --- |
| REINFORCE | 回合结束 | 高 | 0 | 简单但慢 |
| REINFORCE with baseline | 回合结束 | 中 | 0 | 较稳 |
| Actor-Critic | 每步 | 低 | 有 (bootstrapping) | 最快 |

### 7.2 何时用哪个？

| 场景 | 推荐 |
| --- | --- |
| 简单任务、教学 | REINFORCE |
| 任务有清晰回合边界 | REINFORCE with baseline |
| 任务连续、奖励稀疏 | **Actor-Critic** |
| 大规模深度 RL | **A2C / A3C / PPO** |

### 7.3 PPO 是什么？

**PPO（Proximal Policy Optimization）** 是目前最流行的策略梯度算法之一。它在 AC 基础上加了 clip 机制，**防止策略更新过大**。

如果你想继续深挖，PPO 是必学。

## 8. 策略梯度 vs Q 学习：全方位对比

### 8.1 范式对比

| 维度 | Q 学习 (DQN) | 策略梯度 (PG) |
| --- | --- | --- |
| 学什么 | Q(s, a) | π(a\|s) |
| 策略来源 | argmax Q | 直接采样 |
| 动作空间 | 离散 | 离散 + 连续 |
| 策略类型 | 确定性 | 随机性 |
| 训练信号 | TD 误差 | 实际回报 |
| 训练稳定性 | 较稳 | 较不稳 |
| 训练效率 | 较高 | 较低 |

### 8.2 直观比喻

**Q 学习**：先有个老师 (Q 表) 告诉你每个动作多少分，你选最高的。
**策略梯度**：你直接练手感 (π)，靠最终胜负反馈调整。

### 8.3 学术界主流

现代深度 RL 三大家族：

| 家族 | 代表 | 特点 |
| --- | --- | --- |
| Value-based | DQN 改进 (Rainbow) | 离散动作 |
| Policy-based | REINFORCE | 通用 |
| Actor-Critic | A2C, PPO, SAC | **当前主流** |

## 9. 训练技巧与常见坑

### 9.1 必学技巧

#### 1. 折扣因子 γ

- 太小：短视
- 太大：方差爆炸
- 推荐：0.9 ~ 0.99

#### 2. 学习率

策略网络对 lr 很敏感。
- 太大：策略崩溃
- 太小：学得慢
- 推荐：1e-3 ~ 1e-4

#### 3. 标准化奖励

```python
reward = (reward - mean) / (std + 1e-8)
```

减少不同任务奖励尺度差异。

#### 4. 梯度裁剪

```python
loss.backward()
clip_grads(model, max_norm=0.5)
optimizer.update()
```

防止梯度爆炸。

#### 5. 熵正则

往损失加一项 `-0.01 * entropy`，鼓励策略不要过早变确定（保留探索）。

### 9.2 常见坑

| 坑 | 现象 | 解决 |
| --- | --- | --- |
| **梯度爆炸** | loss = NaN | 梯度裁剪 |
| **奖励稀疏** | 一直不学 | reward shaping |
| **策略过早收敛** | 永远选一个动作 | 熵正则 |
| **策略震荡** | 反复横跳 | 减小 lr |
| **Critic 跟踪不上** | δ 一直大 | V 网络学习率调大 |

### 9.3 调试清单

1. 打印每回合 `total_reward` —— 应该**总体上升**
2. 打印 loss_v / loss_pi —— 应该**收敛**
3. 打印 `mean(π)` —— 不应该太快极端化
